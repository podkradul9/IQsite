# TestLab — сайт с тестами и платной подпиской

Каркас в стиле iqmo.ru / testometrika.com: светлый пастельный дизайн, 4 теста, оплата
результата после прохождения, подписка с автопродлением через ЮKassa, отмена без логина.

## Тесты
- **IQ Тест** — 12 вопросов на логику (`iq-full`)
- **Тест на скорость реакции** — нажать, когда фон станет зелёным, 5 раундов, среднее в мс (`reaction-speed`, отдельная механика — `ReactionTest.jsx` / `ReactionResult.jsx`)
- **Готова ли ты / готов ли ты к серьёзным отношениям** — отдельные версии для девушек и парней (`relationships-girls`, `relationships-guys`)
- **Насколько ты привлекательна(ен)** — для женщин и мужчин (`attractiveness-women`, `attractiveness-men`)

Про тесты на привлекательность: они оценивают уверенность, зрительный контакт, самоподачу и
стиль общения, а не внешность — это специально сделано так, чтобы даже низкий результат
звучал конструктивно, а не обидно. Так меньше риск негативной реакции пользователей и жалоб.

Все тесты, кроме случаев, где явно указано `freePreview: true`, показывают пейволл **после**
того, как человек ответил на все вопросы — это уже заложенная механика.

## Оплата и подписка
- Пробный период: **10 ₽ за 3 дня**
- Далее автоматически: **100 ₽ каждые 30 дней**, до отмены
- Модалка оплаты (`src/components/PaywallModal.jsx`) воспроизводит вид скриншота: цена,
  таймер, поле email, два чекбокса согласия со ссылками на документы

### Про таймер в модалке
Таймер обратного отсчёта — мягкий визуальный акцент, который просто останавливается на
00:00:00, когда доходит до нуля (не зацикливается и не создаёт ложное впечатление, что
"цена вырастет" — такого текста нигде нет). Если добавите текст вида "успей, потом будет
дороже" при том, что цена на самом деле не меняется — это уже попадает под понятие
недобросовестной рекламы (вводящая в заблуждение информация о сроках/условиях предложения,
ст. 5 ФЗ "О рекламе") и может привести к жалобам в ФАС. Технически в коде это ничем не
грозит, но лучше держать в голове при доработке текстов.

### Про "невидимую" регистрацию в модалке
Чтобы не показывать отдельный экран регистрации (как в примере), модалка при вводе email
сама создаёт аккаунт через `supabase.auth.signUp` со случайным паролем — человек его нигде
не вводит. **Важно**: в настройках Supabase (Authentication → Providers → Email) нужно
отключить "Confirm email", иначе после регистрации не будет активной сессии и оплату нельзя
будет создать сразу же. Возврат в личный кабинет по этому email — через "Войти по ссылке"
на странице входа (magic link, уже реализовано — ничего дополнительно настраивать не нужно).

## Юридические документы
`src/data/legalDocs.js` + `src/pages/LegalDoc.jsx` — публичная оферта, политика
конфиденциальности, пользовательское соглашение, тарифы, согласие на обработку данных.
**Это шаблоны, не готовый юридический текст** — сформулированы по структуре типичной
оферты подписочного сервиса, но с полями вида `[Название ИП]`, `[ИНН]` для заполнения.
Я не юрист — перед публикацией сайта их обязательно должен проверить юрист, особенно
формулировки про автопродление подписки (это то, что чаще всего проверяют при жалобах).

## Мелкие доработки этого раунда
- Вход по ссылке на email (magic link) — закрывает пробел для аккаунтов, созданных
  через модалку оплаты со случайным паролем, который никто не вводит и не знает
- **Важный фикс**: `.gitignore` не исключал `.env` — реальные ключи Supabase могли
  случайно уйти в git-репозиторий. Теперь `.env` игнорируется, `.env.example` — нет
- Юридические документы (`legalDocs.js`) переведены на формат самозанятости:
  ФИО + ИНН вместо ИП/ООО, без ОГРНИП
- `robots.txt` для индексации поисковиками
- Код каждой страницы грузится отдельным чанком (`React.lazy` + `Suspense`) —
  меньше вес первой загрузки вместо одного файла на весь сайт
- Страница 404 вместо белого экрана на несуществующих адресах
- SPA-фолбэк для Netlify/Vercel (см. выше) — без него ломались бы прямые ссылки на любую страницу
- Спиннер вместо белого экрана, пока грузятся данные (`src/components/Spinner.jsx`)
- Сброс прокрутки наверх при переходе между страницами (`src/components/ScrollToTop.jsx`)
- Модалка оплаты: закрытие по Escape, клик по фону, блокировка скролла страницы под ней,
  автофокус на поле email, `aria-modal`/`role="dialog"` для скринридеров
- Кольца фокуса на всех кнопках/ссылках для навигации с клавиатуры
- Брендированный favicon, meta-описание и Open Graph теги вместо дефолтных от Vite

## Дизайн-система
Пересобрана вокруг темы самого продукта — тестирования — а не общего "приятного SaaS":
- **Цвета**: `ink` (#14162B, тёмные панели и текст), `paper` (#F5F5FB, фон), `marker`
  (#FF4438, единственный акцентный цвет — как красная ручка учителя) — заданы как
  токены Tailwind v4 в `src/index.css` (`@theme`), используются как `bg-ink`, `text-marker` и т.д.
- **Шрифты**: Unbounded (заголовки, цифры результата) + Manrope (текст, кнопки) — `font-display` / `font-sans`
- **Мотивы**: кружки-варианты ответов как в экзаменационном бланке (`TestPage.jsx`),
  точечная сетка на фоне хиро (`.bg-dot-grid`), круговая шкала результата (`ScoreGauge.jsx`)
- **Движение**: два осознанных момента — заполнение шкалы результата и появление модалки
  оплаты; никакой анимации на каждый hover, `prefers-reduced-motion` уважается

## Настройка Supabase
1. Создайте проект на supabase.com, выполните `supabase/schema.sql` в SQL Editor
2. **Authentication → Providers → Email → выключите "Confirm email"** (см. выше, почему)
3. Project Settings → API → скопируйте `URL` и `anon key` в `.env` (см. `.env.example`)
4. Установите Supabase CLI и задеплойте функции:
   ```
   npm install -g supabase
   supabase login
   supabase link --project-ref <your-project-ref>
   supabase functions deploy create-payment
   supabase functions deploy yookassa-webhook --no-verify-jwt
   supabase functions deploy cancel-subscription
   supabase functions deploy unsubscribe --no-verify-jwt
   supabase functions deploy charge-recurring --no-verify-jwt
   supabase functions deploy send-confirmation-email --no-verify-jwt
   ```
5. Задайте секреты:
   ```
   supabase secrets set YOOKASSA_SHOP_ID=xxx YOOKASSA_SECRET_KEY=xxx SITE_URL=https://ваш-домен.ru
   supabase secrets set RESEND_API_KEY=re_xxx FROM_EMAIL="TestLab <noreply@ваш-домен.ru>"
   ```

### Email через Resend
1. Зарегистрируйтесь на resend.com, получите API-ключ
2. Подтвердите свой домен в Resend (Domains → Add Domain, добавить DNS-записи) —
   без этого письма будут уходить только на ваш собственный адрес с их тестового
   домена `resend.dev`, реальным пользователям ничего не придёт
3. `FROM_EMAIL` должен быть на подтверждённом домене, например `noreply@ваш-домен.ru`
4. Письмо с подтверждением триала и ссылкой на `/unsubscribe` уходит автоматически
   при первом успешном платеже — ничего вызывать вручную не нужно

## ЮKassa — самое долгое звено
Нужен подключённый эквайринг: оформленный ИП/ООО, регистрация на yookassa.ru, проверка
документов (обычно несколько рабочих дней). Сначала получите тестовые ключи и всё проверьте,
боевые подключайте в последнюю очередь. Webhook URL для кабинета ЮKassa:
`https://<project-ref>.functions.supabase.co/yookassa-webhook`

## Хостинг фронтенда
```
npm run build
```
Папку `dist` — на Vercel или Netlify (автодеплой из GitHub). SPA-фолбэк уже настроен
для обоих (`vercel.json`, `public/_redirects`) — без него обновление страницы на любом
адресе кроме `/` показывало бы 404 хостинга вместо самого сайта, а не только на несуществующих
страницах, а буквально на `/dashboard`, `/test/iq-full` и так далее.

## Запуск локально
```
npm install
cp .env.example .env   # заполните своими ключами Supabase
npm run dev
```

## Дальше можно добавить
- Ещё тесты — просто добавить объект в `src/data/tests.js`
- Email-напоминание за день до продления (сейчас есть только письмо о старте триала)
- Письма для входа по ссылке (magic link) идут через встроенный email-сервис Supabase,
  а не через Resend — у встроенного низкий лимит отправок в час, для продакшена стоит
  подключить туда тоже свой SMTP (Authentication → Settings → SMTP Settings)
